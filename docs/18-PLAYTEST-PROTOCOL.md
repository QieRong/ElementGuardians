# 18｜试玩协议（主持脚本 · 记录表 · 判定口径）

目的：用可复查的真人试玩判断“核心体验是否成立”，并把反馈分成**规则要变 / 参数要调 / 信息表达要改**三类，先改文档再改游戏再复测。本文不是测试结果；没有实际场次时，全部状态为“未执行”。

## 1. 边界
- 首轮 3 人只是筛查，不是统计显著结论；不得写成“玩家普遍认为”“已商业验证”。
- 脚本/自动化跑圈只验证逻辑与数值，不替代真人；真人数据与脚本数据分开记录。
- 主持人不替玩家操作、不提示策略、不评价对错；只按分级提示规则解围。
- 不收集与服务无关的隐私；录屏/录音需口头或书面同意，可随时停止。

## 2. 场次准备
| 项 | 要求 |
|---|---|
| 版本 | 固定 commit/构建包；记录 Godot 版本、分辨率、窗口模式 |
| seed | 3 个固定 seed（如 20261018 及另外两个记录在表内）；同一玩家尽量同 seed 对比 |
| 设备 | 记录 CPU/GPU/内存/屏幕尺寸；低端机另记（若无低端机写“未测”） |
| 录制 | 屏幕录制 + 计时器；失败局也保留 |
| 材料 | 本文件、记录表、问卷、知情同意说明 |
| 时长 | 单人 30–40 分钟：说明 5 分钟 + 游玩 15–20 分钟 + 访谈 10 分钟 |

## 3. 主持脚本
### 3.1 开场（照读，不补充策略）
> “这是一个 3×3 棋盘上召唤守卫、合成升级、抵挡 6 波敌人的小游戏，一局大约 5–8 分钟。我想看的是操作是否清楚、难度是否合理，不是考你。遇到不知道怎么操作可以问，但我不会告诉你该怎么打。可以随时停止，录屏只用于本次分析。”

### 3.2 分级提示（只在玩家卡住 ≥20 秒时升级一级）
| 级别 | 做法 | 记录 |
|---|---|---|
| L0 | 不提示，观察玩家自己找 | 卡住时长、点击了哪些控件 |
| L1 | 指出相关区域：“左下角是操作区” | 哪一句提示让玩家继续 |
| L2 | 解释规则：“同类型同等级的两个守卫可以合成” | 解释后是否立即理解 |
| L3 | 代操作（仅最后手段） | 必须记录，且该场次不能算“无需解释可完成” |

### 3.3 禁止
- 不诱导“你应该先召唤”“先合成再开波”等策略；
- 不在玩家失败时说“没关系/这波本来就难”；
- 不追问“是不是很好玩”，改用具体行为与选择题。

## 5. 后测问卷（1–5 分，5 为最同意）
1. 我知道第一步该做什么。
2. 我能看懂金币、基地生命和波次的含义。
3. 火/冰/雷的差异我能说出来。
4. 我的选择（召唤位置、合成、强化）对结果有影响。
5. 难度增长是逐步的，不是突然致死。
6. 一局时长合适。
7. 我愿意再玩一局。
开放问题：
- 哪一刻最困惑？当时想做什么？
- 如果只能改一件事，你希望改什么？
- 你会怎么向朋友描述这个游戏（记录原话，用于检验一句话体验）。

## 6. 判定口径（与 `03-BALANCE.md` 试玩表一致）
| 假设 | 指标 | 首轮门槛 | 不成立时的首选动作 |
|---|---|---|---|
| 10 秒理解操作 | 首次召唤/合成/开波用时与提示次数 | 至少 2/3 人 L0 完成召唤与开波 | 改 UI 文案/高亮，不改规则 |
| 金币前两波稀缺 | 第 1 波结束金币、想召唤次数 | 至少 2 人出现“钱不够/主动留钱” | 调初始金或召唤费（需用户拍板） |
| 合成是取舍 | 合成次数、合成后是否补位 | 每局 1–4 次，无人“见同色必合” | 改教学/合成收益表达，不擅自改倍率 |
| 三类型有差异 | 非火单位出场率、强化选择 | 至少 2 人主动选非火或非伤害强化 | 调类型特性或敌人组合 |
| 压力递进 | 每波漏怪与 HP 曲线 | 无“前 3 波满血、第 6 波瞬败”断层 | 调波次间隔/数量（需记录并复测） |
| 5–8 分钟 | 实际局长 | 3 局中至少 2 局落在区间 | 优先调刷怪间隔，不硬改记录 |

判定只写“成立/不成立/证据不足”，并附样本量与原始记录路径；不得四舍五入成“基本成立”。

## 7. 反馈回改流程
1. 汇总：把每条反馈标为 **规则 / 参数 / 表达** 三类；同一问题多人重复出现才升级优先级。
2. 先改文档：规则→`02`；参数→`03`+XLSX/CSV；表达→`06`；关卡→`04`。
3. 再改游戏：同步 CSV、跑 `sync_config.py --check` 与 `validate_config.py`，按 `08` 回归。
4. 复测：同 seed/同脚本对照 + 至少 1 名新玩家；记录“改前→改后”。
5. 更新 `tracking/DECISIONS.md`（若涉及规则取舍）与 `13-PORTFOLIO.md`（只写有证据的结论）。
