## 页面与语言选择

- 主菜单右上角始终有“语言图形 + 当前语言自身名称”，最小触控区域48×48 CSS px。不要仅显示齿轮、国旗或缩写；不加入账号、联网和商店。
- 点入口自底部展开单列抽屉。标题固定双语“语言 / Language”；六项依次为 `简体中文`、`繁體中文`、`English`、`한국어`、`日本語`、`Русский`。自称保持原语言，不随当前界面全部翻译，用户切错后仍能找回。
- 选项整行可点，最小48px高；使用单选圆点、勾选和边框共同表达。点行只修改草稿，不立即关闭。底部“应用”始终可见；应用后刷新界面、保留当前页面和游戏进度，关闭抽屉。原型仅保存本地预览偏好，不涉及游戏存档。
- 右上关闭、遮罩点击、系统返回/ESC取消草稿，原选择不变；不把点击内容区空隙解释为关闭。背景失去输入焦点，键盘焦点限制在抽屉，关闭回到入口；上下键可选语言，Enter/Space应用或操作当前按钮。
- 小屏抽屉最多占可用高度，列表独立滚动，标题与应用固定；底部给手势条留安全区。长屏不拉成全屏设置页。原型采用系统dialog，拖动手势关闭未实现，不作为本轮通过条件。
- 当前预览仅翻译菜单和手机HUD/按钮文案，非中文文案为待母语复核的草案。最终游戏文本应使用稳定ID、Godot Translation资源和显式地区码（zh_Hans/zh_Hant/en/ko/ja/ru），缺失项回退简中并记录开发日志，不显示键名。避免拼接语序不同的句子和按国旗猜语言。

### 各语言标题排版

- 简中“元素守卫”、繁中“元素守衛”保持完整一行；英文按完整单词换行，俄文按完整词组换行。
- 日语明确分为“エレメント”与“ガーディアンズ”两行，按语义居中；禁止末行只剩“ズ”。韩语只在词组空格断行，不能拆出一个孤立音节。
- 主标题与英文品牌行分层，统一水平中心和左右边距，不强求各语言字数相同。禁止拉伸字体。按钮允许自然两行但行内不挤压图标；副文案按词组换行。
- 五种视口均逐字测量标题实际行片段，检查末行孤字、标题/主按钮交叠；日本语/俄语等长文本另存预览并人工目检。

## 手机尺寸与布局

720×1280继续作为逻辑设计坐标；未修改引擎、项目分辨率或路线。移动端是本轮设计目标，当前仓库仍是单机Windows原型，Android/iOS打包另行裁决。

| 设备视口 CSS px | 检查重点 |
|---|---|
| 320×568 | 最小屏，长标题换行、语言列表、底部按钮 |
| 360×640 | 常规16:9，主操作层级 |
| 390×844 | 长屏，顶部47/底部34px安全区模拟 |
| 430×932 | 大屏，顶部44/底部34px安全区模拟 |
| 412×915 | Android长屏，顶部24/底部24px安全区模拟 |

- 使用可用视口和安全区，不在截图外套手机壳。菜单背景cover等比裁切；品牌区可换行，主操作靠底但避开手势条，语言入口避开刘海。
- HUD和操作栏独立排版，保留48px触控高度；手机功能文字通常14–20px，语言行16px，标题按宽度28–52px。不同语言允许两行，禁止为俄语/日语无下限缩小字体。
- 战场按宽、高中较小比例居中等比显示，空余区域留纸纹/留白。路线、九格中心、入口、基地仍取原JSON；不拉伸、不加120px偏移，不通过改地图适配屏幕。
- **P2待解决：小屏棋盘触控。** 76逻辑像素按手机缩放后会小于44 CSS px，尤其320×568。不能用相互重叠的透明点击区伪称达标。工程前需选定局部放大交互：PREP点击棋盘区域打开3×3放大操作区，各格至少48px，选格/源→目标后直接反馈；保留原世界位置、规则与非弹窗路径。放大操作区仍是提案，本轮没有实现或宣称已验证。若不采用放大方式，则小屏棋盘操作验收保留FAIL。战斗中不提供此入口。
- 超宽平板最大内容宽720px，横屏暂不设计可玩流程；后续按平台能力决定锁竖屏或显示旋转提示，不擅自修改工程配置。
