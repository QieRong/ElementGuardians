## 里程碑与决策闸门
- **第一个有效里程碑**：不依靠作弊开关、能用固定三塔完成从第一波到第六波的完整战斗。
- 当基本开局到胜负闭环不成立，禁止开始新的美术大批量生成或元素共鸣。
- 不允许用“AI 自动声称成功”当成测试；没有 Godot 时明确阻塞点，提供下一步命令。
- 到第7天若 P0 还未完工，直接冻结 P1 新玩法，优先把最小版本做成可演示且不崩溃的作品。

## Sprint任务拆解与先后依赖
- S1a: 解析 CSV、状态 GameSession、固定路径、敌人生成移动
- S1b: 静态 3 塔部署、自动选目标、扣血/死亡/漏怪幂等事件
- S1c: 6 波状态转换 + 结算统计 + 固定seed测试
- S2a: 9格占用/玩家点选与明确错误反馈
- S2b: 经济原子消费与随机召唤（4/3/3）
- S2c: 升级合法性和Lv倍率，攻防回归
- S3a: 冰 slow + 雷 chain 功能正确性
- S3b: 强化候选生成、叠层、数值计算、UI卡片
- S4a: 用户界面、菜单/暂停/重开、比例适配
- S5a: 内部 5 seed对照、真人试玩、问题改进与作品集取证

## 每个 Sprint 的提交条件
功能截图/日志 + 配置校验 + `python tools/verify_starter.py`（含 `check_docs.py`）+ Godot parse + 自动断言 + 手工关键流程，均记录命令和结果，写 `tracking/CHANGELOG.md`。不得先宣称全部实现再补证据。
阶段 7 的试玩反馈按“规则变化 / 参数调整 / 信息表达”分类，先改文档再改游戏并复测；脚本对照不能当作真人通关率。
