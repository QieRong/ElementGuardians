## 组件规格与数据归属

| 组件 ID（文档用） | 消费信息 | 布局／状态 | 输出或操作边界 |
|---|---|---|---|
| MenuTitle | 固定标题与副标题 | 页面细则 MENU | 纯文字，不含调试状态 |
| PrimaryButton | 动作名、可用性、禁用原因 | 纸层＋文字，至少60×60目标 | 只表达用户意图，不自行扣金币 |
| HudStat | wave_index／base_hp／gold | 三栏，28px，数字不省略 | 运行值由游戏快照提供；制图为独立样例 |
| PhaseLabel | MENU／PREP／COMBAT等 | 本稿仅显示准备中／战斗中 | 不自建计时器或状态判定 |
| RouteLayer | 地图 JSON 的 path／entry／base | 独立路线、箭头与基地层 | 不按远景透视改路 |
| BoardSlot | index、occupant、level、selected | 固定76×76，共九个 | PREP 选格；COMBAT 不提供操作选中态 |
| GuardThumb | fire／ice／lightning＋level | 上部角色，下部元素／Lv条 | 不混用其他角色头像，Lv3不能出现升级箭头 |
| EnemyView | 敌人类型、位置、hp | 只沿真实路径，小血条不压住邻单位 | 主图第1波仅 grunt，不画提前出现的Boss |
| ActionBar | 状态、选格、金币 | 召唤／取消／开波或只读进程 | PREP→COMBAT后召唤、合成禁用；只读进程无按下态 |
| Feedback | 最近操作结果、禁用主因 | 24px，最多两行 | 无副作用；不能把失败写成已经扣钱或成功 |

以上是后续组件职责提案，不是已经存在的类名、API 或新增代码任务。具体节点与脚本等到工程接入阶段再按现有架构决定。

## 格内空间与切图计划

- 每格本地坐标：主体窗口 (8,2,60,48)；文字条 (4,50,68,24)；外轮廓向格内画。相加不得超过76px。
- 文字条采用“火 Lv1／冰 Lv2／雷 Lv3”同一结构，24px；占用格不叠加格号。完整名字与源格号放底部提示，空格显示0–8。
- 字体真实字宽未知，68px是否容纳文字必须实测。若溢出，先换用窄的等级数字排法、在主体角放元素形状并把文字条仅保留“Lv1”；完整元素名留在提示区，不能缩小到24px以下。
- 裁切保存原图不覆盖，记录 source_id、源 SHA256、裁切矩形、导出尺寸、导出 SHA256、修复方式。透明像素外围须在黑蓝和骨白底各检查一次。
- 冰／雷疑似残片先对照实际源图；源图不可得时只记录问题并采用不包含残片的主体裁切。涉及图像修复时优先内置 image_gen，后续不得静默用 Python 修改图片。
- 不重新生成三名守卫，不把某个异兽头像替换成雷霆守卫；小尺寸识别问题优先用裁主体和元素标识解决。
