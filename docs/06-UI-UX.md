# 06｜UI / UX 与交互规范

## 整体视觉风格（2026-10-20 已确认，D005 / D009）
全游戏统一采用 **纸雕秘仪风（Papercraft Techno-Occult Fantasy）**：分层剪纸、哑光纸张、机械图腾与秘仪符号。以黑蓝作为背景与暗部、骨白作为文字和纸层主体、锈红作为重要操作与危险提示的强调色，冰青与酸黄作少量辅助色。元素识别继续配合图标、文字与形状，避免只靠颜色。

- 材质与层次：通过纸片叠层、切边和柔和投影表现层次；机械纹样与图腾作为边框、角饰或局部装饰，保持文字区域清晰。
- 页面统一：主菜单、战斗 HUD、底部操作区、强化卡、暂停面板和胜负结算沿用同一套纸层、边框、字体层级与配色；具体排版继续遵循本文件的布局与交互规则。
- 控件状态：正常、按下、选中、禁用使用清楚的边框/纸层变化与文本反馈；锈红同时用于强调与危险提示时须用文案或图标区分含义。
- 素材依据：使用 `07-ASSETS.md` 对应的现有素材包映射；尚缺素材时可使用符合该风格的原生绘制或 SVG 功能占位。**不允许拷贝竞品 UI 截图做素材**。

本节确认的是整体风格方向；各页面最终视觉稿、具体色值与组件效果仍须在设计及 Godot 实机中确认。文档更新不代表素材已接入工程。

## 交互
- 点击空格显示青色轮廓 + 格号；点召唤扣费并显示元素图标、等级。
- 点击已有塔设为“源”，再点另一个已有塔尝试合成；规则满足成功，否则显示可理解错误。点击取消可清空选择。
- 战斗期间所有准备态按钮变灰并有文本说明；不能只靠颜色区分不可用状态。
- 暂停按钮可延到 P1；游戏退出和回主菜单清楚提示丢失本局进度。
- 每波开始/结束显示 1 行状态文本，金币获得/扣除显示动画或文本变化；Boss 出场有明显标识。
- 强化 3 选 1卡片必须展示具体加成与最大叠层，选中后返回准备阶段。
- 结算显示“胜利/失败”和本局 seed、击杀、漏怪、时长、消耗金币/已获得金币、合成次数，支持一键重开。

## 可用性最低线
- 字体主体 24–32 设计像素，触控目标≥60×60 设计像素；文字和面板对比度清晰。
- 颜色之外使用形状/文字区分：火图标 F、冰 I、雷 L、Boss B（占位）；不要求玩家仅通过色相分辨。
- 控件在 720×1280 下完全可见，窗口缩放 0.75 与 1.0 下不溢出；长提示可换行。
- 正式素材前优先验证对比度、识别距离、按钮禁用态与消息提示，避免以美术完成度掩盖可操作性问题。

界面不是按钮清单；每个元素都必须说明它展示哪个对象的哪个属性、在什么状态下可见、点击后改变什么。

|---|---|---|---|---|

| 顶部 HUD | 基地 10/10 | Run.base_hp / economy_params.base_hp | 无 | HP≤0 立即转失败页，数字不再变化 |
| 顶部 HUD | 金币 40 | Run.gold | 无 | 扣费/入账用数字跳动 + 一行文本，不只靠颜色 |
| 顶部 HUD | 当前状态：准备中 | Run.state | 无 | 状态文案与按钮可用性必须一致 |
| 战场 | 3×3 格子 | Slot.index / occupant / selected / merge_hint | 点选源格、目标格 | 空/占用/选中/可合成四种外观，另附格号 |
| 战场 | 守卫 | Guard.type_id / level / cooldown | 点选 | 冷却中显示灰色进度环；Lv3 显示满级标记 |
| 战场 | 敌人 | Enemy.hp / effective_speed | 无（自动） | 被减速时加冰色描边；Boss 单独血条 |

## 内容数量变化时的排版规则
- 强化卡固定为“最多 3 张”：候选不足 3 时按实际数量居中排列，空位不拉伸、不补假卡。
- HUD 数字（金币/HP/波次）按当前数据可能达到的最大位数预留宽度（由 CSV 计算），右对齐；不用省略号截断。
- 提示文案最多 2 行，超出换行；最小字号 24 设计像素；更长的说明放到暂停页/帮助页，不挤压战场。
- 结算统计固定 6 项，超出的次级指标（每波收入等）放入第二列或折叠区，面板整体不滚动。
- 未来若增加元素/敌人类型，召唤按钮不扩展成列表（类型仍由 RNG 决定），只在结果与图鉴中呈现。
- 界面中出现数量上限（如 3 张卡、9 格）必须来自规则或配置，不能把效果图里的排版数量当规则上限。
