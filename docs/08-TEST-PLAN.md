## 3. 策划调优测试（和程序正确性分开）
每批至少 5 个固定 seed 跑基线。记录 `seed、版本、波次、总怪数、击杀数、漏怪数、金币收支、三塔类型与等级、强化、玩家操作、每波用时、最终胜负`；真人测试额外记录是否理解规则、策略选择理由、难度感受。**自动化机器跑圈不能冒充真人数据。**

## 4. 失败证据
发现 FAIL 必须记录：复现步骤、当前 commit、配置版本、seed、错误日志、截图/短录像（可得时）、期待结果、实际结果和严重度（Blocker/Critical/Major/Minor）。不得通过静默降低测试阈值来标绿。

## 5. 启动阶段最小门槛
Sprint 1 完成后必须满足 `SES-01, WAV-01, WAV-02, WAV-03, ENM-01, ENM-02, SES-02` 的可复现测试。该阶段**仅允许自动化夹具**跳过未实现的强化选择，逐波自动推进；真实玩家状态机第1–5波必须在Sprint 3实现 `UPGRADE` 后再正式验收。召唤/合成/强化尚未完成时，须明确对应项为 SKIP，而非通过。

## 3 证据规范（PASS/FAIL/SKIP 都要能复查）
- 每条 PASS 必须附：执行命令、原始输出（或日志路径）、日期、版本/commit、seed。
- 证据统一放 `logs/test_runs/YYYYMMDD_<ID>_<seed>.log`；截图放 `logs/screenshots/YYYYMMDD_<ID>.png`（目录不存在时创建，不把截图散落在根目录）。
- SKIP 必须写原因与解除条件（例如“本机无 Godot 4.4.1，L1 未执行”），不能只写 SKIP。
- FAIL 按 Blocker/Critical/Major/Minor 记录，修复后追加复测记录，不删除旧记录。
- 脚本退出码 0 不等于用例通过：必须断言具体数值/状态（例如金币、等级、HP、敌人数），否则记为“未验证”。
