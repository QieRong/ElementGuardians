### 文案与行为边界

- “开始游戏”指向目标玩家流程 PREP，不表示当前工程已实现；视觉稿外部说明注明目标设计状态。
- 无存档依据，不出现“继续游戏”；不出现“第1关／第2关”选择，本项目是六波的单关原型。
- 退出入口只表示退出程序，不捏造退出确认弹窗或云存档行为。
- 设置／暂停不放入本次主稿；这是画面范围选择，不删除既有规范中允许的后续功能。
- “验证 CSV 配置”等工程诊断控件不放进面向玩家的目标菜单；本轮不删除现有骨架代码。

### MENU 细节检查

标题不能压在月轮放射刻线或古堡尖顶上；必要时调整装饰与背景裁切，不能靠粗重发光补可读性。开始／退出要有明显层级，不能两个同等锈红。角饰不伸入中文字形、按钮点击边界与底部说明。

HUD每栏内部把24px辅助图形／标签与28px数字分开排，不将“图标＋整段文字”挤成一行后再缩小字体。金币完整显示至少三位数字；实际选定字体后核对200／224px栏宽，必要时在栏内分两行，不改HUD高度或截断数字。

当前CSV的保守显示上界为：初始60＋全部敌人基础奖励383＋六次波末奖励120＋最大每杀额外4×59只＝799金币。即使无法在首波前获得满层加成，此式仍是保守上界；不扣召唤费用、不计漏怪收入。该数只用于预留字宽，不是新的金币上限、实际收入或可达性证明；后续配置改动须重算。

现行 UI 文档中的 0–140／140–1060 是概念区，不是地图几何。本提案依据 JSON 的战场 y=120、h=960 细化排版，未修改现行规范或地图。状态文字位于 y=122–154；实际制图需与入口标签及路线外缘一并检查。

### 真实地图叠加约束

路线中心依次通过：

```text
(80,190) → (640,190) → (640,440) → (80,440)
         → (80,810) → (640,810) → (640,980)
```

- 入口 (80,190)，基地 (640,980)，不增设分叉、内环、第二基地或中途出口。
- 路线美术带宽建议 40px，箭头必须沿上述方向；40px 是视觉提案，不改路径或碰撞。
- 路线和单位的显示均用全屏坐标；战场容器 y=120 不能导致再次给路径 y 加 120。
- 第一段路径外缘按提案为 y=170–210；入口标签可放在 (32,132,144,32)，不压在路线或状态文字上。
- 基地标识提案占 (602,942,76,76)，其核心仍在 (640,980)；基地说明可放 (490,1030,206,32)，避开终段路线。
- 背景圆台、桥、瀑布均是远景，不构成玩法路段。功能路线使用连续清楚的纸石带，不沿背景透视重新布线。

COMBAT 主图数据是静态排版样例：可理解为三次召唤后开波，但不声称特定 seed 真实抽到了该结果。格3／4／5的组合恰与诊断夹具一致，制作记录必须明确“非正式初始阵容、非真实回放”。PREP 合成样例是独立展示，不伪装成同一局连续记录。

主图第1波只出现grunt，可拟使用005窥视蛛机作为视觉对应；006／007／008不提前出现。敌人若只在y=190的首段路线，守卫通常尚未够到，不能为了画面热闹强加越距攻击或命中特效；具体射程按当时CSV核对。

合成沿用源→目标直接尝试，不新增“先选两格，再点合成按钮”的第三步。022 合成图仅作为状态局部图的说明图标；不在三按钮操作栏里再塞一个合成确认按钮。

### 错误和边界文案

| 条件 | 目标文案／表现 |
|---|---|
| 金币19且已选空格 | “金币不足，召唤需要20金币”，不扣钱 |
| 未选格 | “请先选择空格” |
| 目标已占用 | “格子已有守卫，请选择空格” |
| 九格已满 | “棋盘已满，合成可腾出空格” |
| 正在 COMBAT | “战斗中不可召唤或合成” |
| 无选中但点取消 | 控件禁用；共享提示区不弹无关错误 |
| 多条件同时不满足 | 优先阶段限制→满格→选格有效性→金币；显示一个主要原因，错误尝试反馈不覆盖事实 |

不在本轮决定空白区域点击取消、手动锁定目标或键盘操作。已有规范的歧义不靠视觉稿补成新规则；明确“取消选择”按钮即可表达本次设计。
